# سرور TamizChat

سروری که پشت TamizChat است: اتاق‌ها، چت متنی، فایل، تخته‌ی نقاشی مشترک، نقش‌ها و
مدیریت، صدا و تصویر، و بات‌های موسیقی — همه در یک باینری Go با یک دیتابیس SQLite
کنارش.

نه `.env` دارد، نه دیتابیس جداگانه، نه Redis، و نه فایل تنظیماتی که دستی ویرایش
کنید. همه چیز از یک پنل مدیریت تعاملی تنظیم می‌شود که همان باینری، وقتی بدون
آرگومان اجرا شود، باز می‌کند.

## پیش‌نیازها

| | |
|---|---|
| سیستم‌عامل | لینوکس، ویندوز یا مک (برای سرور واقعی: لینوکس) |
| CPU/RAM | هرچه باشد. یک VPS کوچک راحت اجرایش می‌کند |
| Go | ۱.۲۴ به بالا، **فقط اگر از سورس بیلد می‌کنید** |
| داکر | اختیاری، فقط برای LiveKit |

باینری بدون CGo ساخته می‌شود، پس هیچ چیزی لازم نیست کنارش نصب شود — نه نسخه‌ی
خاصی از libc، نه پکیج SQLite.

## نصب

### از روی ریلیز

</div>

```bash
wget https://github.com/<you>/tamizchat-server/releases/latest/download/tamizchat-linux-amd64
chmod +x tamizchat-linux-amd64
sudo mv tamizchat-linux-amd64 /usr/local/bin/tamizchat
```

<div dir="rtl">

### از سورس

</div>

```bash
git clone https://github.com/<you>/tamizchat-server.git
cd tamizchat-server
make build          # یا: go build -o tamizchat ./cmd/tamizchat
```

<div dir="rtl">

برای همه‌ی پلتفرم‌ها یک‌جا:

</div>

```bash
make release        # لینوکس/ویندوز، amd64/arm64، در پوشه‌ی dist/
```

<div dir="rtl">

> **موقع دانلود ماژول‌ها `403 Forbidden` گرفتید؟** `proxy.golang.org` و
> `sum.golang.org` سرویس‌های گوگل‌اند و از بعضی کشورها بلاک‌اند. یک بار Go را به
> یک آینه وصل کنید تا بیلد کار کند:

</div>

```bash
go env -w GOPROXY=https://goproxy.io,direct
go env -w GOSUMDB=off
```

<div dir="rtl">

اگر آن کند بود، `goproxy.cn` یا `mirrors.aliyun.com/goproxy/` جایگزین‌اند. آن
`,direct` انتهای آدرس را حذف نکنید.

## اولین اجرا

</div>

```bash
tamizchat            # پنل مدیریت را باز می‌کند
tamizchat run        # سرور را اجرا می‌کند
```

<div dir="rtl">

اولین اجرا فایل `data/tamizchat.db` را در پوشه‌ی جاری می‌سازد. همه چیز داخل همان
است: تنظیمات، اتاق‌ها، نقش‌ها، بن‌ها، بات‌ها و کاربران شناخته‌شده.

در پنل، این سه کار را به همین ترتیب انجام دهید:

**۱ — اسم سرور را بگذارید.** گزینه‌ی `2 → General`. نام سرور، و اگر نمی‌خواهید
سرور باز باشد، یک رمز.

**۲ — خودتان را ادمین کنید.** تا وقتی کسی نقش Admin را نداشته باشد، هیچ‌کس
نمی‌تواند اتاق بسازد یا کسی را اخراج کند؛ و این اولین اعطای نقش **عمداً** فقط
روی خود ماشین ممکن است.

- سرور را اجرا کنید (`tamizchat run`) و یک بار با کلاینت وصل شوید تا شناسه‌ی
  کلاینتتان شناخته شود.
- در پنل: گزینه‌ی `5` (Known users) آن را نشان می‌دهد.
- گزینه‌ی `7 → 5` (Grant a role to a user) ← نقش **Admin** ← خودتان.

> نقشی که هنگام اجرای سرور داده شود بلافاصله اعمال می‌شود؛ پنل بعد از هر تغییر
> می‌پرسد «الان اعمال شود؟».

**۳ — اتاق بسازید.** گزینه‌ی `6 → n`.

## اجرای دائمی (systemd)

گزینه‌ی `12` پنل، یک فایل یونیت برای **همین** نصب می‌نویسد؛ با مسیرهای واقعی
پرشده و سخت‌شده (`ProtectSystem`، `ReadWritePaths`، کاربر غیر روت). سپس:

</div>

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tamizchat
sudo systemctl status tamizchat
```

<div dir="rtl">

لاگ‌ها:

</div>

```bash
journalctl -u tamizchat -f
```

## با دامنه، بدون TLS

این همان حالت رایج است: دامنه‌ی `chat.example.com` را دارید، رکورد A آن به سرور
وصل است، و فعلاً گواهی نمی‌خواهید. **کار می‌کند، و اینجا دقیقاً نوشته چطور** — به
همراه چیزی که با این انتخاب می‌پذیرید.

> **چه چیزی را می‌پذیرید.** بدون TLS همه چیز به‌صورت متن ساده جابه‌جا می‌شود:
> پیام‌ها، رمز سرور، و فایل‌ها. هر کسی بین کاربر و سرور — اپراتور اینترنت، یک
> وای‌فای عمومی، شرکت هاستینگ — می‌تواند بخواند و تغییر دهد. بعضی شبکه‌ها هم
> ترافیک WebSocket ساده را می‌بندند. این حالت برای شبکه‌ی خصوصی یا مورد اعتماد
> خوب است؛ قبل از اینکه غریبه‌ها را راه بدهید [TLS را روشن کنید](#با-tls). پانزده
> دقیقه کار است و رایگان.

### راه کوتاه: بدون هیچ پروکسی

TamizChat را مستقیم روی پورت ۸۰ اجرا کنید و دامنه را به آن بدهید.

</div>

```bash
tamizchat
```

<div dir="rtl">

- گزینه‌ی `2 → 1` **Listen address** ← `:80`
- گزینه‌ی `2 → 2` **Public host** ← `http://chat.example.com`

پورت زیر ۱۰۲۴ اجازه می‌خواهد. به‌جای اجرا با روت، همان قابلیت را به باینری بدهید:

</div>

```bash
sudo setcap 'cap_net_bind_service=+ep' /usr/local/bin/tamizchat
sudo systemctl restart tamizchat
```

<div dir="rtl">

و پورت را باز کنید:

</div>

```bash
sudo ufw allow 80/tcp
```

<div dir="rtl">

از این به بعد کلاینت‌ها به `chat.example.com` (یا `ws://chat.example.com/ws`) وصل
می‌شوند، بدون اینکه پورتی تایپ کنند.

**آدرس listen تنها تنظیمی است که reload اعمالش نمی‌کند** — پورت یک بار هنگام
اجرا bind می‌شود، پس بعد از تغییرش سرویس را restart کنید.

### راه بهتر: nginx جلوی سرور، باز هم بدون TLS

اگر روی همان ماشین چیز دیگری هم سرو می‌کنید، یا بعداً TLS می‌خواهید، این راه
می‌ارزد — آن‌وقت TLS فقط یک دستور `certbot` فاصله دارد.

</div>

```bash
sudo apt install nginx
```

<div dir="rtl">

فایل `/etc/nginx/sites-available/tamizchat`:

</div>

```nginx
server {
    listen 80;
    server_name chat.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        # بدون این دو خط، WebSocket ارتقا پیدا نمی‌کند و هیچ چیز کار نمی‌کند.
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # سوکت‌ها ساعت‌ها باز می‌مانند؛ پیش‌فرض آن‌ها را سر ۶۰ ثانیه می‌بُرد.
        proxy_read_timeout 3600s;

        # باید از uploads.max_size_mb بیشتر باشد، وگرنه فایل بزرگ در nginx رد می‌شود.
        client_max_body_size 64m;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/tamizchat /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

<div dir="rtl">

سپس در پنل:

- گزینه‌ی `2 → 1` **Listen address** ← `127.0.0.1:8080` (فقط nginx به آن می‌رسد)
- گزینه‌ی `2 → 2` **Public host** ← `http://chat.example.com`
- گزینه‌ی `2 → 7` **Trusted proxies** ← `127.0.0.1`

> **حتماً trusted proxies را ست کنید.** بدون آن، هر اتصال از دید سرور از
> `127.0.0.1` می‌آید، پس محدودیت «تعداد اتصال به‌ازای هر IP» کل اینترنت را یک
> کاربر حساب می‌کند: یک کلاینت پرسروصدا می‌تواند در را روی بقیه ببندد.

restart کنید و تمام:

</div>

```bash
sudo systemctl restart tamizchat
```

<div dir="rtl">

### اضافه‌کردن TLS در آینده

هیچ‌کدام از کارهای بالا هدر نمی‌رود:

</div>

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d chat.example.com
```

<div dir="rtl">

بعد **Public host** را به `https://chat.example.com` تغییر دهید. certbot خودش
کانفیگ nginx را بازنویسی می‌کند؛ TamizChat همچنان پشت آن روی HTTP ساده گوش
می‌دهد.

## با TLS

دو راه دارد و اولی توصیه می‌شود.

**پشت یک reverse proxy** — همان بالا، با `certbot`. تنظیم `tls.enabled` را خاموش
بگذارید: nginx کار TLS را می‌کند و TamizChat روی loopback می‌ماند.

**مستقیم در TamizChat** — وقتی چیزی جلویش نیست. گزینه‌ی `2 → 3` پنل (TLS): مسیر
گواهی و کلید را بدهید و `tls.enabled` را روشن کنید. گواهی هنگام اجرا بررسی
می‌شود و سرور با گواهی خراب بالا نمی‌آید، به‌جای اینکه بی‌صدا بدون TLS اجرا شود.

## صدا و تصویر (LiveKit)

خود TamizChat هیچ صدا و تصویری جابه‌جا نمی‌کند. توکن امضا می‌کند و مدیریت را
اعمال می‌کند؛ **LiveKit** مدیا را می‌برد. چت متنی، اتاق‌ها، فایل و تخته‌ی نقاشی
بدون آن هم کار می‌کنند.

۱. LiveKit را بالا بیاورید (فایل‌های آماده‌ی داکر و یک سناریوی بدون دامنه و بدون
TLS در [docs/LIVEKIT.md](docs/LIVEKIT.md) هست).
۲. گزینه‌ی `2 → 9` پنل (Voice and video):

- `livekit.url` ← مثلاً `ws://127.0.0.1:7880`
- `livekit.api_key` و `livekit.api_secret`
- `livekit.enabled` را روشن کنید

آدرس API سرور از همان URL ساخته می‌شود (`ws://` ← `http://`).

دسترسی هر کاربر در LiveKit دقیقاً آینه‌ی دسترسی‌های او در TamizChat است، پس
کلاینتی که درباره‌ی حق انتشارش دروغ بگوید را خود LiveKit رد می‌کند.

## بات موسیقی

بات مثل یک شرکت‌کننده‌ی مستقل وارد اتاق می‌شود و پلی‌لیست پخش می‌کند؛ کنترلش از
داخل کلاینت است، برای هر کسی که دسترسی `control_bots` دارد.

- بات به **LiveKit** نیاز دارد (بالا). و به هیچ چیز دیگر — نه Ingress، نه Redis.
- آهنگ‌ها به‌صورت **Ogg/Opus** ذخیره می‌شوند؛ کلاینت هر چیزی را که آپلود کنید
  (mp3, m4a, wav, flac) قبل از ارسال تبدیل می‌کند. سرور همان بسته‌ها را دست‌نخورده
  منتشر می‌کند، پس هیچ‌وقت صدا را دیکد نمی‌کند.
- ادمینی که `manage_bots` دارد، بات‌ها را از پنل مدیریتِ کلاینت می‌سازد و
  پلی‌لیست‌ها را پر می‌کند؛ گزینه‌ی `10` پنل خط فرمان هم همین کار را می‌کند.
- این موزیک **دائمی** است — برخلاف فایل‌های اتاق، از ری‌استارت جان سالم به در
  می‌برد — پس حواستان به `bots.quota_mb` (سهمیه‌ی هر بات) باشد و از `bots.dir`
  کنار دیتابیس بکاپ بگیرید.

## پشتیبان‌گیری

گزینه‌ی `13` پنل. بکاپ با `VACUUM INTO` گرفته می‌شود، پس **حین اجرای سرور امن
است** — برخلاف کپی‌کردن فایل که ممکن است وسط نوشتن یک صفحه گیر بیفتد.

یک cron شبانه روی همان دیتابیس:

</div>

```bash
0 4 * * * cd /opt/tamizchat && sqlite3 data/tamizchat.db \
  "VACUUM INTO 'data/backups/nightly-$(date +\%Y\%m\%d).db'"
```

<div dir="rtl">

بازگردانی فقط وقتی سرور **خاموش** است ممکن است، و دیتابیس فعلی پاک نمی‌شود بلکه
نگه داشته می‌شود.

**داخل بکاپ هست:** تنظیمات، اتاق‌ها، نقش‌ها، بن‌ها، بات‌ها، کاربران شناخته‌شده.
**داخل بکاپ نیست:** چت، فایل و نقاشی — این‌ها عمداً موقتی‌اند و با خالی‌شدن اتاق
پاک می‌شوند. موزیک بات‌ها هم روی دیسک است، نه در دیتابیس.

## مرجع تنظیمات

همه‌ی موارد زیر در پنل (گزینه‌ی `2`) ویرایش می‌شوند، در دیتابیس ذخیره می‌شوند و
زنده اعمال می‌شوند — به‌جز آدرس listen.

| بخش | چه چیزی را پوشش می‌دهد |
|---|---|
| `server` | نام، پیام خوش‌آمد، رمز، حداکثر کاربر |
| `network` | آدرس listen، هاست عمومی، heartbeat، محدودیت هر IP، پروکسی‌های مورد اعتماد |
| `tls` | گواهی و کلید، روشن/خاموش |
| `users` | طول نام کاربری |
| `rooms` | تعداد اتاق، ظرفیت پیش‌فرض، اندازه‌ی تاریخچه، پاک‌سازی هنگام خالی‌شدن |
| `chat` | طول پیام، محدودیت نرخ، استیکر |
| `uploads` | روشن/خاموش، سقف حجم، سهمیه‌ی هر اتاق، پوشه‌ی ذخیره |
| `paint` | روشن/خاموش، سقف خط‌ها، محدودیت نرخ |
| `livekit` | آدرس، کلید و سکرت API، روشن/خاموش |
| `bots` | پوشه‌ی ذخیره، سقف حجم هر آهنگ و هر بات |
| `backup` | پوشه، تعداد نگه‌داشتن |
| `log` | سطح لاگ (در زمان اجرا تغییر می‌کند) |

گزینه‌ی `3` همه‌ی تنظیمات را با مقدار فعلی چاپ می‌کند؛ گزینه‌ی `4` یکی را به
حالت پیش‌فرض برمی‌گرداند.

## پورت‌ها

| پورت | برای چه | چه زمانی لازم است |
|---|---|---|
| ۸۰ یا ۴۴۳ | کلاینت‌ها | همیشه (یا ۸۰۸۰ اگر نه پروکسی دارید نه دامنه) |
| 7880/tcp | سیگنالینگ LiveKit | صدا/تصویر |
| 7881/tcp | ICE روی TCP | جایگزین وقتی UDP بسته است |
| 50000-60000/udp | مدیای LiveKit | صدا/تصویر |

کانال کنترلی پنل فقط روی **loopback** گوش می‌دهد، با توکنی که هر اجرا عوض می‌شود؛
هرگز نباید از بیرون در دسترس باشد.

## عیب‌یابی

**کلاینت وصل نمی‌شود.** دستور `curl http://<host>/healthz` را بزنید؛ اگر جواب داد،
مشکل از فایروال یا پروکسی است. در nginx، آن دو هدر `Upgrade` را چک کنید.

**صدا کار نمی‌کند.** گزینه‌ی `11` پنل مقدار `MediaOK` را نشان می‌دهد. اگر خاموش
است، یکی از سه تنظیم LiveKit خالی است یا LiveKit در دسترس نیست.

**بات می‌گوید در حال پخش است ولی کسی صدایی نمی‌شنود.** تقریباً همیشه LiveKit:
اول ببینید صدای آدم‌ها کار می‌کند یا نه. سرور هر آهنگی را که سرو می‌کند در سطح
debug لاگ می‌کند (`tamizchat run -log debug`).

**همه از 127.0.0.1 دیده می‌شوند.** `network.trusted_proxies` ست نشده — [بالا](#راه-بهتر-nginx-جلوی-سرور-باز-هم-بدون-tls)
را ببینید.

**تنظیمی را عوض کردم ولی اتفاقی نیفتاد.** فقط `network.listen_addr` نیاز به
restart دارد. بقیه وقتی پنل می‌پرسد «الان اعمال شود؟» اعمال می‌شوند، یا از مسیر
`11 → reload`.
